# 版本更新记录 (Changelog)

本文档记录「个人重要资料整理库」项目的核心功能演进、安全性加固、缺陷修复与架构升级历史。

## [v1.7.0] - 2026-09-20

### 🛡️ 第五轮渗透测试漏洞深度加固与存证防伪体系重构
- **存证核验防伪造体系 (P1)**：
  - 新增服务端存证票据签发接口（`POST /api/export/ticket`），用户发起导出前必须先向服务端申请票据，校验用户在所选分类下真实持有材料，杜绝空壳存证；
  - 存证编号（`verifyCode`）与官方材料汇总（`manifestSummary`）改为服务端权威随机生成与构建，并使用 `AUTH_SECRET` 签发有时效限制（15分钟）的密码学票据（Ticket）；
  - 存证记录入库接口（`POST /api/export/record`）严格验票，废弃客户端自定编号与汇总摘要，阻断任意伪造编号、虚假全 0/全 a 指纹以及 `./etc/passwd`、`../跳转` 等路径穿越与注入攻击；
  - 引入服务端 HMAC-SHA256 存证签名（`signature`），公网核验接口（`/api/verify`）严格校验签名完整性与指纹真实性。
- **审计日志真实 IP 伪造防御彻底闭环 (P1)**：
  - 修正 `src/lib/audit.ts` 中 `extractClientIp` 的配置判断缺陷，全面废弃对客户端请求头（`X-Forwarded-For`、`X-Real-IP`、`CF-Connecting-IP`）的默认采信；
  - 统一直接采信 Node.js 底层 TCP 连接层注入的物理 IP（`x-socket-ip`），仅在显式配置 `TRUST_PROXY=true` 时按受信代理链规则解析，彻底杜绝审计证据链被篡改。
- **上传请求体与大文件 413 硬拦截 (P1)**：
  - 在底层 Node 原生 HTTP 服务入口（`deploy/server-entry.js`）拦截 `Content-Length > 20MB + 64KB` 的超大请求体，直接断开并返回 `413 Payload Too Large`，防止超大请求进入 Node/Next.js 内存缓冲导致 OOM DoS；
  - `POST /api/documents` 文件大小校验统一规范返回 `413` 状态码，`/api/verify` 超大包查验同样规范响应 `413`。
- **`/api/verify` 频控与防探测惩罚机制 (P2)**：
  - 全局单 IP 查询限流收紧至 15 次/分钟；
  - 增加 404 不存在记录探测惩罚：单 IP 连续查询不存在或伪造记录超过 5 次立即触发 `429 Too Many Requests`，强力阻断对存证编号的枚举与爆破。
- **注册频控收紧与账号大小写/空格一致性修复 (P3)**：
  - 注册接口（`POST /api/auth/register`）限流收紧为单 IP 15 分钟内最多 5 次，第 6 次直接阻断返回 429；
  - 修复注册落库时存储原始未清洗账号导致大写/首尾空格邮箱登录偶发 401 的缺陷，统一转为小写与去除首尾空格存储。
- **测试数据与历史伪造记录彻底清理**：
  - 全面清理第五轮渗透测试期间遗留的所有测试账号（`pent5_*`、`13800020205`、`pentC*`、`rl178*` 等）；
  - 清理历史测试伪造的三条存证记录（`CA-202609-4GTT-2VYG`、`CA-202609-CCCC-DDDD`、`CA-202609-AAAA-BBBB`）。

## [v1.6.0] - 2026-09-17

### 🛡️ 渗透测试深度加固与系统高可用性保障（第三轮与第四轮检测修复）
- **防宕机与图像解压炸弹防御 (R4-P0)**：
  - 上传接口（`/api/documents`）增加 `Content-Length` 前置拦截（超 20MB 立即响应 413），增加单用户总空间配额限制（1GB）；
  - Sharp 图像处理接入像素上限闸门（`limitInputPixels: 16M`），分辨率严格限制 `<= 4096px`，彻底防御恶意大图或解压炸弹瞬时打满内存导致系统 OOM 宕机；
  - 进程级 Sharp 并发排队机制升级（`withSharpSlot`），设最大排队等待上限，保障小规格服务器在并发场景下的内存平稳。
- **客户端 IP 真实性与防伪造防护 (R4-P1)**：
  - 在服务底层 HTTP 监听层（`server-entry.js`）抓取不可伪造的真实 TCP 物理连接 IP（`x-socket-ip`）；
  - 审计日志与限流器默认采信物理连接 IP，杜绝客户端通过伪造 `X-Forwarded-For`、`X-Real-IP`、`CF-Connecting-IP` 篡改审计日志与污染溯源证据链。
- **敏感档案元数据完整门控 (R4-P1)**：
  - 完善二次验证元数据屏蔽策略：未获授权时，`GET /api/documents` 统一将敏感证件 `title` 降级为通用证件类型名（严格遵守无正反面后缀规范），`fileName` 统一为 `"已加密材料"`，`note`、`meta`、`certificate` 置为 `null`，严密防守“用户拥有何种证件”档案清单。
- **API 统一防缓存指令 (R4-P2)**：
  - 全局中间件统一为所有 `/api/*` 接口响应注入 `Cache-Control: private, no-store, no-cache, max-age=0, must-revalidate` 与 `Pragma: no-cache`，消除共享缓存或代理泄露敏感响应数据的风险。
- **二次验证状态机与合法用户防锁死优化 (R3-P1, R4-P3)**：
  - 二次验证授权双轨落地：成功时既向客户端下发 `sensitive_ok` Cookie，同时在服务端将会话 `sid` 纳入授权白名单（10 分钟），保障授权在会话存续期内绝对生效，消除虚假成功审计；
  - 优化锁定逻辑：优先校验密码，正确密码立即放行并清除错误计数；仅针对错误猜测进行阶梯式延时与 429 锁定，彻底避免合法用户被恶意试探锁死。
- **端到端文本加密 (E2ET) 全面落地 (R4-新 3)**：
  - 敏感证件备注、结构化字段及证书登记备注在提交前均由客户端使用 DEK 进行 AES-GCM 加密（前缀 `E2ET:`）；
  - 服务端与数据库只存密文字符串，导出时屏蔽未解密文本，客户端展示时透明解密，真正实现文件与文本双维度端到端加密。
- **客户端与服务端 CSV 公式注入防御 (R3, R4)**：
  - 网页前端与后端导出的 `材料清单.csv` 与 `证书汇总.csv` 全面接入 `csvCell` 中和函数，自动对 `[=+\-@\t]` 字符转义，防御电子表格宏与公式执行攻击。
- **纯 HTTP 环境下 SHA-256 存证指纹计算兼容修复**：
  - 解决现代浏览器在非安全上下文（纯 HTTP IP 访问）中 `window.crypto.subtle` 为 `undefined` 导致“`Cannot read properties of undefined (reading 'digest')`”的前端打包与验真报错，全面切换为纯 JS `@noble/hashes` 引擎，实现纯 HTTP 环境下 100% 顺畅导出。

## [v1.4.0] - 2026-09-09

### 🚀 核心修复与体验优化
- **二次验证即时解密渲染（免手动刷新）**：
  - 修复二次验证弹窗（`SensitiveVerifyModal.tsx`）验证成功时提前触发 `close() -> onClose()` 导致待执行动作（`pendingAction.current` 打开大图）被提前清空为 `null` 的生命周期缺陷。
  - 解耦表单重置（`resetForm`）与取消关闭（`handleCancel`），输入密码后立即执行调起大图动作，大图秒级弹出并自动解密展示，彻底消除用户必须手动刷新网页的困扰。
- **大图查看器状态联动与缓存清理**：
  - 在 `ImageViewer.tsx` 中新增 `verifyTick` 依赖监听，在二次验证状态刷新后自动清空当前内存缓存，强制重新解密当前图片与多面缩略图，无需重新加载网页。

### 🔐 E2EE 密钥强一致性与防覆盖加固
- **改密流程密钥原子同步**：
  - 重构设置页改密逻辑（`settings/page.tsx`），严禁静默吞没 `rewrapDekData` 异常。
  - 优先复用内存已解锁的 DEK（`getDek()`）派生新包裹密钥，并在一次数据库操作中原子提交新密码哈希与 `newWrappedKey`，杜绝改密后密码与密钥脱离同步。
- **防止密钥盐覆盖铁律**：
  - `src/app/api/e2ee/setup/route.ts` 新增 `hasDocs` 检查，对已有加密档案的用户，服务端强制拦截任何尝试重置/更改 `e2eeSalt` 的请求。
  - `src/lib/e2ee.ts` 的 `ensureDek` 函数禁止对已有加密盐或档案的用户回退生成新密钥，若密码不匹配则直接抛错引导进入自愈流程，彻底防止旧文件密钥丢失。
- **旧建档密码平滑迁移（Self-Healing）**：
  - 当登录密码与当前包裹密钥不匹配时，二次验证弹窗自动切换至“原建档密码”，验证后在客户端浏览器完成真实 DEK 解包并用新密码重新包裹存盘。
- **云端数据库密钥恢复**：
  - 从备份库 `dev.db.bak_20260909_pre_sync` 恢复了管理员用户的原始有效加密盐与包裹密钥，在保留最新登录密码的同时成功解封所有物理加密归档。

### 🌐 纯 HTTP 与非安全上下文兼容
- **纯 JS 密码学引擎**：
  - 全站端到端加解密完全运行于 `@noble/hashes`（PBKDF2-HMAC-SHA256）与 `@noble/ciphers`（AES-256-GCM），不依赖浏览器原生 Web Crypto 的安全上下文限制，纯 HTTP 运行无阻。
- **剪贴板复制降级方案**：
  - 针对非 HTTPS 环境缺少 `navigator.clipboard` 的限制，`src/lib/format.ts` 实现多层降级（自动使用 `document.execCommand("copy")`），支持一键复制身份证号、姓名等文本，消除控制台未捕获报错。

## [v1.0.0] - 2026-08-21

### 🏗️ 初始架构上线
- **五大档案分类体系**：
  - 个人身份与户籍、学业与成绩、资质与技能证书、个人经历与实践、重要资产证明。
- **端到端加密（E2EE）体系建立**：
  - 基于 DEK（数据加密密钥）+ KEK（密钥加密密钥）的双层信封加密机制；
  - 物理文件在客户端本地加密为 `E2E1` 二进制密文流后上传存储，服务端零明文落盘。
- **安全门禁体系**：
  - 二次验证密码保护机制与 30 天信任设备管理；
  - 基于 SQLite + Prisma 的轻量级高可靠本地数据库架构；
  - Next.js 14 App Router + Tailwind CSS 现代化全栈实现。
