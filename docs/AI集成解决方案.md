# 简册 · 个人电子档案袋 —— AI 功能集成解决方案

> 面向团队:AI 工程架构设计文档
> 核心前提:这是一个**对隐私极度敏感**的大学生电子档案系统(身份证件 AES-256-GCM 端到端加密、密码二次验证)。所有 AI 能力设计必须以**"身份信息绝不上云、非敏感材料可走云端"**为最高优先级红线。

---

## 一、现状盘点:你们已有 70% 的地基

在动手前先明确一个好消息——项目里**已经沉淀了扎实的 AI 基础设施**,方案不是从零搭建,而是把现有碎片**按隐私边界整合成一套完整的能力矩阵**,并补齐缺失环节。

### 已具备的能力

| 模块 | 文件 | 现状 |
|------|------|------|
| **AI 配置体系** | `src/lib/ai-config.ts` | 用户自定义 API Key(AES-256-GCM 加密存储)、BaseURL、模型;含**完整 SSRF 防护**(字面量 + DNS 级私网拦截)、连接测试、OpenAI 协议封装、重试与错误友好化 |
| **本地 OCR** | `src/lib/ocr.ts` + `src/workers/ocr.worker.ts` | **浏览器端 Web Worker 本地识别**,图片不出网,含自动转正 |
| **证件解析** | `src/lib/doc-recognition.ts` | 身份证/驾驶证/护照/通行证等 20+ 类型字段解析、正反面/主副页判定、证号校验徽标 |
| **AI 路由 ×5** | `src/app/api/ai/*` | `extract-fields`(字段提取)、`archive-check`(档案完备性自检)、`quality-check`(图像质量)、`resume-bullet`(简历要点)、`export-suggest`(导出建议) |
| **到期提醒引擎** | `src/lib/expiry.ts` | 纯规则引擎:身份证/通行证/驾驶证/银行卡/学生证学年有效期,已过期/即将到期(30天)/长期判定 |
| **隐私范式范例** | `archive-check` 路由 | **示范了正确做法**:identity 类只传数量、绝不暴露具体标题;非敏感类才传标题 |

### 缺失的环节

1. **云端 OCR 增强**:现有只有本地 OCR,复杂版式(奖状、成绩单)识别率有限,且未接入视觉大模型
2. **RAG 智能问答**:没有任何检索增强生成能力
3. **主动式提醒调度**:`expiry.ts` 是纯函数,未被调度为定时/登录时主动提醒
4. **隐私分级路由层**:敏感/非敏感材料走不同 AI 通道的逻辑散落各处,未集中统一

## 二、核心设计:按敏感度分级的 AI 能力矩阵

你已确认的隐私边界:**身份信息(身份证/通行证/护照/户口簿等)禁止上云;奖状类等非敏感材料大部分可以走云端。**

据此把材料分为两级,AI 能力按级路由:

```
┌─────────────────────────────────────────────────────────────┐
│                     AI 能力矩阵 (能力 × 通道)                │
├───────────────────┬─────────────────────────────────────────┤
│                   │  ① 本地/私有化通道 (绝不上云)            │
│                   │  - 浏览器 Web Worker 本地 OCR            │
│                   │  - 服务端私有化小模型 (可选 Ollama)       │
│                   │  - 纯规则引擎 (到期判断,已在 expiry.ts)   │
│                   ├─────────────────────────────────────────┤
│                   │  ② 云端通道 (仅非敏感材料)               │
│                   │  - 用户自配大模型 API (已有 ai-config)    │
│                   │  - 视觉大模型 OCR 增强                    │
│                   │  - RAG 问答、智能归档、洞察生成            │
└───────────────────┴─────────────────────────────────────────┘
```

**分级原则(写入代码的红线)**:

| 材料大类 | 分类 key | 能否上云 | 说明 |
|---------|---------|---------|------|
| 身份证件 | `identity-*` | **❌ 禁止** | 标题/内容/字段一律不得发往第三方。只传"数量" |
| 获奖证书 | `certificate-*` | ✅ 允许 | 默认走云端(奖状类你已确认大部分可以) |
| 经历证明 | `experience-*` | ✅ 允许 | 实习/志愿/社团证明,非敏感 |
| 活动照片 | `photo-*` | ✅ 允许 | 非敏感 |
| 作品集 | `portfolio-*` | ✅ 允许 | 非敏感 |

> 注意:`archive-check` 已示范 identity 只传数量。**这条规则必须扩展为所有 AI 路由的强制约束**——统一收敛到分级路由层,而不是各路由自己判断。

## 四、四大 AI 功能落地方案

按你确认的四项功能,逐一给出实现路径。**优先级排序**:OCR → 智能归档 → 到期提醒 → 智能问答(问答依赖前者的数据质量与 RAG 基建)。

### 功能 1:OCR 证件识别(分级双通道)

**现状**:已有本地 Web Worker OCR(`ocr.ts`) + 证件解析(`doc-recognition.ts`)。缺云端增强。

**方案**:
```
上传材料
  ├─ 判定材料类别
  │   ├─ identity-* (身份类)  → ① 本地 OCR (图片不出网) → doc-recognition 解析
  │   └─ 非敏感类 (奖状/证书)  → ② 云端视觉大模型 OCR (识别率更高,复杂版式)
  └─ 结果统一回填草稿 → 用户确认 → 存储 (加密)
```

**落地步骤**:
1. **复用现有本地 OCR** 作为 identity 类的唯一通道(隐私红线)
2. **新增云端 OCR 路由** `src/app/api/ai/vision-ocr/route.ts`:调用视觉大模型(VL,已具备 `isVisionModel()` 判定),识别非敏感材料,返回结构化文本
3. **智能命名**:云端 OCR 结果交给 LLM,按 AGENTS.md 规范生成**纯证件类型标题**(严禁 `-正面`/`-反面` 后缀),`side` 属性单独归位
4. **分级路由**:新增 `ai-router.ts` 统一判断,杜绝身份类误入云端

**隐私保障**:身份类 OCR 全程本地,图片字节流绝不出网。这是硬约束。

---

### 功能 2:智能归档整理(自动归类 + 打标签)

**现状**:已有 `extract-fields`(字段提取),缺自动归类到五大分类 21 子类。

**方案**:
- 上传后,由云端 LLM(非敏感材料)或规则(身份类)自动推断:
  - 所属**顶级分类**(identity / certificate / experience / photo / portfolio)
  - 所属**子类**(如 `certificate-award`、`experience-intern`)
  - **推荐标题**(纯证件类型名,符合 AGENTS.md)
  - **关键词标签**
- 结果作为**回填草稿**,用户确认后才落库(保持"AI 辅助、用户决策")

**新增路由**:`src/app/api/ai/classify/route.ts`
- 入参:文件识别文本(非敏感)或文件名+类别推断(身份类走规则映射)
- 出参:建议的 `categoryId`、`title`、标签
- 约束:身份类用规则引擎(基于 `doc-recognition` 判别类型 → 映射到 identity 子类),不上云

---

### 功能 3:智能提醒 / 洞察(主动式服务)

**现状**:`expiry.ts` 是纯函数引擎,未被调度。

**方案**:
1. **规则引擎调度化**(不依赖 LLM,免费且精准):
   - **登录后触发**:扫描该用户全部材料 `meta` 字段中的有效期 → 用 `expiry.ts` 判定 → 有"即将到期(30天)"或"已过期"则在前端展示提醒条
   - **服务端 cron 每日扫描**(新增 `src/lib/expiry-scheduler.ts`):对活跃用户聚合到期情况,可选推送(邮件/站内信)
2. **AI 洞察增强**(非敏感数据):LLM 汇总用户档案,生成"材料完整性建议""补办优先级""升学/求职材料准备清单"——复用 `archive-check` 模式

**隐私注意**:到期判断走 `expiry.ts` **纯本地规则**,完全不调用 LLM,连非敏感数据都不需要上云——这是最高性价比的一环。

---

### 功能 4:AI 智能问答(基于个人档案的 RAG)

这是最重、也是体验提升最明显的一环。基于用户自己的档案问答,如"我有哪些省级证书""哪些材料快到期了"。

**方案**:
1. **索引构建(仅非敏感材料)**:
   - 对 `certificate` / `experience` / `photo` / `portfolio` 的元数据(标题、机构、级别、获奖时间、备注)+ OCR 文本建立检索索引
   - **SQLite 自带 FTS5 全文检索**即可起步,零新增依赖(推荐);规模大了再上 embedding 向量库
   - **identity 类绝不入索引**(红线)
2. **RAG 流程**:
   ```
   用户提问 → 检索相关档案(非敏感) → 组装上下文 → LLM 生成回答(引用来源) → 返回
   ```
3. **新增路由**:`src/app/api/ai/ask/route.ts`(RAG 检索 + LLM 生成)、`src/app/api/ai/ask-index/route.ts`(索引重建)
4. **安全约束**:
   - 检索范围强制 `userId` 过滤(防止越权)
   - identity 数据不进上下文
   - 回答需标注材料来源,方便用户核验

## 五、隐私与安全红线(必须落实的硬约束)

> 这直接呼应你确认的边界与项目 AGENTS.md。以下每一条都必须落地,不是建议。

### 5.1 数据分级路由(新增 `ai-router.ts`,全路由唯一出口)
- 单一判定函数 `getMaterialSensitivity(categoryKey)`:identity-* 一律返回 `LOCAL`,其余返回 `CLOUD`
- 所有 AI 路由强制经过它,杜绝"某个路由忘了判断"导致身份数据外泄

### 5.2 身份类材料三重防护
1. **不入索引**:RAG 索引构建时显式排除 identity 类
2. **不传内容**:发给 LLM 的上下文,identity 类只含"数量",绝不含标题/字段/内容
3. **不上图**:身份类 OCR 走本地 worker,图片字节流不出网

### 5.3 SSRF 防护(已有,需保持)
- `assertPublicAiEndpoint` 的 DNS 级私网拦截已很完善,新路由必须继续调用,禁止绕过

### 5.4 成本滥用防护(已有,需扩展)
- 现有 `checkAiRateLimit` 已覆盖 5 个路由,新增的 `vision-ocr` / `classify` / `ask` 必须接入统一限流

### 5.5 审计日志
- 所有 AI 调用记录 `userId` + 动作 + 是否敏感,便于排查异常(复用 `AuditLog` 或新增 `AiUsageLog`)

### 5.6 严格遵循 AGENTS.md
- 所有 AI 生成的标题 = **纯证件类型名**(如"居民身份证"),**严禁**附加 `-正面`/`-反面`/`·签注` 等后缀;正反面通过独立 `side` 字段标识

## 七、技术选型建议

| 需求 | 推荐方案 | 理由 |
|------|---------|------|
| 云端大模型 | 沿用现有用户自配 API(DeepSeek 等,OpenAI 协议) | 零改造成本,已有完整封装 |
| 视觉 OCR(非敏感) | 用户自配的 VL 模型(如 qwen-vl / gemini) | 已有 `isVisionModel()` 判定 |
| 本地身份 OCR | 现有 Web Worker OCR(Tesseract 类) | 已实现,图片不出网 |
| RAG 检索(起步) | **SQLite FTS5** | 零新依赖,与现有 SQLite 一体 |
| RAG 检索(规模) | 本地 embedding + 向量库(FAISS/Qdrant) | 检索质量更高,但增加复杂度 |
| 私有化推理(可选) | Ollama 本地部署 | 若需更强的本地 LLM 能力 |
| 定时调度 | Next.js Route Handler + 外部 cron,或 `node-cron` | 轻量 |

**决策建议**:RAG 优先用 SQLite FTS5 起步(零依赖),验证价值后再评估向量库;私有化 Ollama 作为可选项,不急。

## 八、风险与权衡

| 风险 | 等级 | 应对 |
|------|------|------|
| 身份类数据误上云 | 🔴 高 | 分级路由层强制 + 审计日志 + 定期核查日志 |
| AI 生成标题违规(带面后缀) | 🟡 中 | LLM prompt 强约束 + 服务端二次校验(正则拦截后缀) |
| RAG 检索越权 | 🟡 中 | 所有检索强制 userId 过滤 |
| 大模型成本失控 | 🟡 中 | 统一限流 + 仅非敏感数据走云端 + 结果缓存 |
| LLM 幻觉(归档/问答误导) | 🟡 中 | 一律"草稿 + 用户确认";问答标注来源可核验 |
